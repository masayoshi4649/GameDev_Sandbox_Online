# 東京湾岸の実地表データ

台場・有明・東雲・豊洲とその周辺について、国土地理院の実水域・道路・海岸線と、国土交通省 Project PLATEAU の写真・標高配信を取得している。海岸の輪郭や道路線は手作業で作成していない。

対象範囲は西経度 139.760、東経度 139.830、南緯度 35.610、北緯度 35.670。データ取得日は 2026 年 10 月 16 日。データの整備年度は下表のとおり異なるため、現在の現地と完全には一致しない。

| データ | 原典 | 取得・加工内容 |
| --- | --- | --- |
| 陸地・水域 | 国土地理院最適化ベクトルタイル、2026 年 7 月 1 日時点 | z16 の実水域 `WA` を統合し、対象範囲から差し引いて陸地を生成。原図形を維持し、細かな重複・不正接触を補正。 |
| 道路 | 同上 `RdCL` | 実道路中心線と道路種別・幅員区分・階層順を保持。タイル端と対象範囲で分割された線分。 |
| 海岸線 | 同上 `Cstline` | 実海岸線の線形を保持。 |
| 航空写真 | PLATEAU-Ortho 2023 と国土地理院全国最新写真（シームレス） | z18 の元写真 3,136 枚を取得し、16 枚ずつ 1,024 × 1,024 画素に結合。配置は z16 の 196 タイルを維持。PLATEAU の透明部分・未整備タイルを同じ z18 の国土地理院写真で補完し JPEG 化。 |
| 地表高 | PLATEAU の公式配信カタログで公開される楕円体高 Terrain-RGB | z15 の実標高画像を 90 枚取得し双一次補間。高さの基準面を変更せず地心座標からゲーム座標へ変換。 |

道路は **11,004 線分**、海岸線は **491 線分**。道路の本数や交通ネットワークの交差点数を意味しない。陸地は **111 ポリゴン**で、内周穴を保持する。

## 精度と高さの基準

原点は経度 139.795、緯度 35.640、WGS84 楕円体高 0 m。WGS84 地心直交座標（ECEF）を原点の ENU へ変換し、`X = East / 10`、`Y = Up / 10`、`Z = -North / 10` とする。建物と地表は同じ変換・同じ高さ基準を使用する。緯度経度の差を一定係数で単純換算しない。

楕円体高は日常的な標高・平均海面高とは異なる。この地域の地表がゲーム座標 Y 約 3～5 に現れるのはそのためで、建物を Y = 0 に下げて合わせる加工は行わない。標高画像の鉛直符号化単位 0.1 m は測量精度を保証するものではない。

写真の z18 配信画像の画素間隔は原点付近で約 **0.49 m**。原典の撮影解像度・測量精度を保証する値ではない。画像を単純に引き伸ばして高解像写真として扱わず、元の z18 タイルを取得して結合する。PLATEAU と国土地理院の双方に z18 写真がない領域だけは z16 へ戻し、子タイルごとに `isLowerResolutionFallback` と元のズーム・URL・画素間隔を記録する。

今回の実取得では 3,136 領域すべてに z18 写真が揃い、低解像代替は **0 件**。PLATEAU を基にする領域 2,353 件、国土地理院だけで補う領域 783 件。PLATEAU のうち 695 件は透明部分を同じ z18 の国土地理院写真で補完した。原点の配信画素間隔は **0.4853 m**。写真 JPEG 合計約 **74.4 MB**、描画地表 JSON 合計約 **63.4 MB**。

z15 の標高画像の画素間隔は原点付近で約 **3.9 m**。これは配信画像の標本間隔であり、元の測量が一律 3.9 m 精度という意味ではない。描画地表は写真 1 枚ごとに **65 × 65 頂点**へ標本化し、頂点間隔は約 **7.8 m**。湾岸の微地形や地物境界の段差を完全再現する密度ではない。低負荷で再生成する場合は `--mesh-size 33 --photo-zoom 16` を指定する。

建物・航空写真・地形・道路には整備時点の差があり、写真の影や工事中の土地、地表と建物基部の局所的なずれが残る。橋梁・地下道路の立体構造は、この道路中心線から自動復元していない。

`widthMeters` は幅員区分の代表値であり、実測道路幅員ではない。公式属性 `vt_width` は「地図表示用の仮想的な幅員」であるため `sourceWidth` にそのまま保存し、実幅員と扱わない。建設を避けるための参考幅員は `widthIsApproximate: true` を明記する。

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `Data/RealWorld/ground.json` | 出典、取得日時、座標系、対象範囲、陸地・水域の外周と穴、道路・海岸線、写真タイル参照、子写真ごとの出典・原本ハッシュ。 |
| `Data/RealWorld/elevation.json` | CPU が読める 513 × 513 の高さ配列。約 2.1 MB。 |
| `Assets/RealWorld/Ground/ortho-16-X-Y.jpg` | 描画用の実写真。 |
| `Assets/RealWorld/Ground/terrain-16-X-Y.json` | 対応する写真地表の頂点と三角形索引。 |
| `Tools/ImportGround/cache/` | 元画像と PMTiles の必要範囲。再実行用キャッシュ。Git 管理対象外。 |

`ground.json` の `lands` と `waters` は `{ points: [[x,z]], holes: [[[x,z]]] }`、`roads` は `{ points, widthMeters, widthRank, sourceWidth, category, level, motorway }` を持つ。`rasters` は `path` と `terrainPath` で画像・地表を参照する。

地表ファイルは `terrainVertices: [[x,y,z,u,v]]` と `terrainIndices: [i]`。写真の UV は左上 `(0,0)`、右下 `(1,1)`。地表頂点数は合計 **828,100**、三角形は合計 **1,605,632**。

写真の配置ズームは `zoom: 16`、原典のズームは `photoSourceZoom: 18`、アトラス寸法は `imageSize: [1024,1024]`。`sourceTiles` に結合した全子タイルの取得 URL・SHA-256・位置・補完情報を記録する。`imagery` に全域の原典枚数・画素間隔・低解像代替件数を記録する。

CPU 高さ配列は `width, height, minX, minZ, stepX, stepZ, heights`。X が先に増加する行優先形式で、`heights[zIndex * width + xIndex]` はゲーム内の Y 座標。描画用三角形・写真を Linux 専用サーバーで読む必要はない。

## 再取得と確認

Python 3.10 以降を用意し、プロジェクトルートで次を実行する。処理は GPU 不要。

```powershell
python -m venv Tools/ImportGround/.venv
& Tools/ImportGround/.venv/Scripts/python.exe -m pip install -r Tools/ImportGround/requirements.txt
& Tools/ImportGround/.venv/Scripts/python.exe Tools/ImportGround/import_ground.py --workers 6 --mesh-size 65 --photo-zoom 18
& Tools/ImportGround/.venv/Scripts/python.exe Tools/ImportGround/validate_ground.py
```

取得処理は欠損標高を検知すると失敗終了する。取得できない地表を推測して生成しない。写真原本の SHA-256、実取得 URL、補完元も `ground.json` に保存する。写真取得は最大 6 並列。404 の未提供情報も保存し、再実行のたびに同じ未整備 URL を照会しない。配信元の更新を反映したい場合は、再実行前に `Tools/ImportGround/cache` を削除する。

CPU 用の陸海・道路・標高を変えず、写真と描画地表だけを更新する場合は次を実行する。

```powershell
& Tools/ImportGround/.venv/Scripts/python.exe Tools/ImportGround/import_ground.py --rasters-only --workers 6 --mesh-size 65 --photo-zoom 18
```

確認処理では 4 地区の陸地と 2 か所の水域、全ポリゴンの妥当性、全地表ファイル・頂点・索引・UV・高さの範囲を確認する。目視確認用の全域画像を `artifacts/real-world-ground-contact.jpg` へ生成する。

## 出典と利用条件

本プロジェクトでは以下を加工して作成している。ゲームの出典表示にもこれらを残すこと。

- **国土地理院最適化ベクトルタイル**： [公式仕様・データ更新情報](https://github.com/gsi-cyberjapan/optimal_bvmap)、[コンテンツ利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html)。最適化ベクトルタイルは基本測量成果ではなく、出典を明示して規約に従い利用できる旨が公式資料に記載されている。対象範囲の抽出・図形処理・座標変換を実施。
- **国土交通省 Project PLATEAU**： [航空写真の公式配信仕様](https://docs.plateauview.mlit.go.jp/datasets/ortho/)、[サイトポリシー](https://www.mlit.go.jp/plateau/site-policy/)。現行ポリシーは PDL 1.0、CC BY 4.0 と互換。出典と加工したことを明示する。写真の JPEG 圧縮・透明部補完と地形への投影を実施。
- **国土地理院 全国最新写真（シームレス）**： [利用区分](https://maps.gsi.go.jp/help/use.html)、[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html)。同利用区分の「基本測量成果以外で出典の記載のみで利用可能」の写真に該当する。PLATEAU 写真の未整備・透明部分を補完するために使用。
- **PLATEAU / Mapterhorn / 国土地理院**： 楕円体高 DEM の [配信カタログ](https://tile.plateauview.mlit.go.jp/tiles/catalog.json)、[TileJSON](https://tile.plateauview.mlit.go.jp/mapbox/tilejson.json?format=png)、[地形の公式説明](https://docs.plateauview.mlit.go.jp/datasets/terrain/)、[Mapterhorn](https://mapterhorn.com/)。取得日の公式カタログ・TileJSON は楕円体高 `mapbox` 配信を公開し、この 3 者の出典を指定していた。地形説明には raster-dem を調整中とする記述が残るため、再取得時は公式カタログを確認する。

表示例：**国土地理院最適化ベクトルタイル、国土地理院 全国最新写真、国土交通省 Project PLATEAU、Mapterhorn を加工して作成**。

Mapterhorn の [原典一覧 JSON](https://download.mapterhorn.com/attribution.json) には、日本の標高原典 `jpdem1a / jpdem5a / jpdem5b / jpdem5c / jpdem10a / jpdem10b` が「国土交通省国土地理院」の「基盤地図情報（数値標高モデル）」として記録されている。その利用条件欄は「国土地理院コンテンツ利用規約／測量法に基づく国土地理院長承認（使用）R 8JHs 131」。この番号は配信元による原典加工の承認表示であり、本ゲームが新たに承認を取得したという意味ではない。
